# HamChat 2.7.5

This release improves HamMem retrieval, response budgeting, and everyday model controls.

## HamMem

- Ollama embeddings run on the CPU by default, leaving GPU memory available for chat. Explicit embedding options can override this default.
- Full selected memory content is included before context planning, rather than cut off by separate memory-packing limits. Model context limits still apply.
- **Maximum memories** and **Minimum relevance** are available beneath **Use HamMem** in the Chat Panel. Defaults remain 5 memories and 0.25 cosine similarity. Relevance excludes weaker matches; it is not a confidence percentage.
- Retrieval preferences persist separately for each user and for guests. Disabling HamMem keeps the chosen values. Existing role permissions and global/admin memory behaviour are retained.

## Generation and context

- Configure **Maximum generation (Thinking + answer)** per Ollama model in Model Manager. The default is 4096 tokens, shared by reasoning and the visible answer.
- Context planning preserves the requested generation allowance by excluding oldest conversation turns from the outgoing request when necessary. Saved conversation history is retained, and status messages report excluded turns and the shared allowance.
- If mandatory input plus the requested allowance cannot fit, HamChat rejects the request before answer generation and explains how to adjust it. Input sizing remains an estimate; models can still stop early or reach their output limit.

## Chat and model controls

- Resend and edit-and-resend replace the selected user turn and its following replies correctly, instead of leaving duplicate turns. Image resends resolve the original content-addressed (CAS) attachment rather than reusing a thumbnail.
- The Model menu now starts with **Unload all models**, including embedding models, and **Load and warm selected model**. Warm-up uses the selected chat model's context allocation without adding messages or changing history. Operations run in the background, report progress and failures, and prevent conflicts with active generation or other lifecycle operations. Unsupported backends are reported clearly.
- Message bubbles explicitly use a 14-point font for text and code, making sizing consistent across application font defaults.

## Compatibility

Database schema remains **2026-08-03.2** and data-layout version remains **1**. This release adds no database or data-layout migration. Model memory requirements and context limits still depend on the model and hardware.
